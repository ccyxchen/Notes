# Cline使用说明

## 设置角色
通过 .clinerules/ 目录来模拟角色。
* 原理：你可以在 .clinerules/ 下创建不同的规则文件（如 backend-dev.md, code-reviewer.md），
里面写入该角色的行为准则和系统提示。
* 使用方式：在对话中通过 @agent-name 来“激活”对应规则，让 Cline 采用该角色的人设进行对话。
* 社区方案：像 BMAD Method 这样的社区项目就是基于这个思路，提供了一套预定义的角色文件
（如 @dev, @architect），安装后即可在 Cline 面板中直接使用。

## 通用设置
对于 Linux 内核这类巨型项目，除了 MCP，还需要组合使用 Cline 的内置功能。
1、配置 .clineignore 文件：在内核根目录创建此文件，排除 Documentation/、tools/、scripts/ 等非核心目录，以及编译产物。这能将 Cline 的初始分析上下文从 200k+ token 削减到 50k 以下，大幅降低启动开销。

2、启用 Memory Bank：通过 .clinerules/memory-bank.md 文件，让 Cline 维护一个结构化的项目知识库。它能让 Cline 在跨会话时记住内核的架构约定、关键数据结构和编码规范，避免每次重新学习。

3、利用 new_task 工具：在 .clinerules 中定义规则，当上下文使用率超过 50% 时，自动提议通过 new_task 工具将任务交接给一个新的、干净的会话。这能有效避免在单一会话中上下文无限膨胀，同时将关键信息打包传递，确保任务连续性。

## 减少幻觉的策略
大型代码库中，模型“编造”不存在的函数或 API 是常见问题。以下 MCP 和策略可以显著改善：

agentMemory：为 Cline 提供持久化、可搜索的内存。通过双向同步，它能确保 Cline 基于项目真实记忆库中的信息来回答，而不是靠猜测。

MCP-coding-assistant：这个 MCP 专门为减少幻觉而设计。它能自动检测项目使用的技术栈，并从官方文档中检索相关文档，为 Cline 提供准确的参考，从而大幅降低编造 API 的风险。

ReOpenSpec：这是一个多智能体编排框架，通过强制执行架构边界和严格的工作流，确保 AI 在大型代码库中的行为是可预测的，不会轻易“跑偏”。

## 设置MCP
在 Cline 中，RAG 功能通常是通过 MCP 服务器来实现的。设置 MCP 服务器是第一步。
* 设置 MCP：在 Cline 面板中，点击顶部的 MCP Servers 图标 -> Configure 选项卡 -> 
Configure MCP Servers 按钮，这会打开 cline_mcp_settings.json 文件。你可以在此文件中
添加 MCP 服务器的配置。

* 设置 RAG：以 mcp-server-ragdocs 为例，这是一个基于 Qdrant 向量数据库的 RAG MCP。你需要先安装并运行 Qdrant 和 Ollama，然后在上述 JSON 文件中添加配置，让 Cline 能够通过自然语言查询你的文档。
### 选择 MCP
以下 MCP 工具能从不同维度显著削减上下文消耗，非常适合大型项目。

| MCP 工具 | 核心功能 | 节省 Token 的原理 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **Redcon** | 上下文预算与压缩 | 对代码库进行确定性排序和压缩，只将与任务最相关的部分打包，输入 token 可削减 **83%** 以上。 | 通用任务，需要快速为当前任务准备最精简的上下文。 |
| **NeuralMind** | 持久化内存与压缩 | 为 Agent 提供项目级的“记忆”，能学习文件间的关联。查询时只返回最相关的代码片段，用 **~800 token** 替代 **~50,000 token** 的文件粘贴。 | 长期、多轮的任务，需要 Agent 记住项目结构和历史决策。 |
| **context-firewall** | MCP 代理与瘦身 | 作为本地代理，将 **50+ 个 MCP 工具整合为 4 个**，并对工具输出（如大型日志、JSON）进行 **60-95%** 的瘦身。 | 当你连接了大量 MCP 服务器，工具定义本身就占用大量上下文时。 |
| **codebone** | 符号搜索与项目地图 | 提供语法感知的代码上下文、符号搜索和项目地图，让 Agent 能进行**精准的符号级查询**，而非读取整个文件。 | 在大型代码库中快速定位函数、类或变量的定义与引用。 |
